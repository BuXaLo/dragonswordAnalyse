# Предварительный анализ боевой системы DragonSword: Awakening

Этот документ фиксирует выводы, которые можно подтвердить по текущим таблицам. Он намеренно не выдаёт предположительные joins или коэффициенты за окончательную формулу.

## 1. Что уже видно в таблицах

### `PCComboData.xml`

Запись содержит отдельные варианты действий персонажа. Для Джерома (`ID=1000013`) в таблице есть, среди прочего:

| `Index` | Описание в исходной записи | Классификация |
|---:|---|---|
| 701 | `닷지` | Уклонение |
| 801 | `점프` | Прыжок |
| 901 | `패시브 - 닷지 공격` | Атака после уклонения |
| 902 | `패시브 - 닷지 공격 - 추가 인풋` | Дополнительный ввод после атаки после уклонения |
| 915 | `패시브 - 대시 공격` | Атака после рывка |
| 502 / 503 | `시그널A_2스택` / `시그널A_3스택` | Варианты сигнального A |
| 2001 / 2051 | `시그널A - 뒤잡기...` | Варианты захвата сзади/мультизахвата |
| 402 | `액티브2 - 반격` | Контратака активного навыка 2 |
| 8001 / 9001 / 9002 / 9011 | варианты улучшения активного навыка 2 | Варианты, связанные с мастер-навыком/кармой/трансценденцией |

Названия приведены как смысловой перевод корейских описаний; для финальной русской формулировки сверять с `PCSkillGrowthData.xml` и `StringData_ru.txt`.

У Логана (`ID=1000030`) видны:
- `Index=10` — атака после уклонения;
- `Index=915` — атака после рывка;
- `Index=11` — сигнальный A при выходе из воздушного состояния (`시그널A - 에어 해제 시`).

У Вероники (`ID=1000016`) видны:
- `Index=901` — атака после уклонения;
- `Index=915` — атака после рывка;
- `Index=302` — попадание активного навыка 1;
- `Index=602` — попадание сигнального B;
- `Index=606` — вариант сигнального B для multi-mount;
- `Index=8001` — дополнительная/замещающая запись, связанная с мастер-навыком и атакой после уклонения/рывка.

**Важно:** `Index` — это индекс действия в системе комбо, а не номер удара в обычной цепочке LMB. Для восстановления цепочки обычной атаки надо получить все записи персонажа и связать их с анимационными действиями.

## 2. `PCActionDamageData.xml`: что считать одним попаданием

В таблице встречаются строки с одинаковыми `Name`, `ActionIndex`, `AnimationName`, `ComboIndex`, но разными `AttackKey`. Поэтому одна анимация может включать множество отдельных attack events. С другой стороны, в таблице могут присутствовать дубликаты по другим измерениям/вариантам данных.

Для анализа необходимо сохранять как минимум:
`Name`, `ID`, `ActionIndex`, `AnimationName`, `ComboIndex`, `AttackKey`, `DamageWeight`, `HitGroupIndex`.

`DamageWeight` нельзя интерпретировать как «процент ATK» без подтверждения формулой или игровыми тестами. Аналогично `AttackWeight` из `PCComboData`/`PCComboLevelData` — отдельное поле и не должно заменять `DamageWeight`.

## 3. Параметры комбо по уровням

`PCComboLevelData.xml` хранит `Level`, `ComboID`, `GroupIndex`, `SubGroupIndex`, `AttackWeight`, `CoolTime` и параметры воздействия. Пример записей для Lute показывает изменение `AttackWeight` от уровня к уровню. Но связь `PCComboLevelData.ComboID` с `PCComboData.ID` не следует считать прямой: в примерах `PCComboData.ID` — ID набора персонажа, а уровневый `ComboID` принимает отдельные значения. Перед объединением нужно определить составной ключ и проверить его на всей таблице.

## 4. Схема событий

Предварительная цепочка анализа:

`PCCharacterData` → идентификатор/таблица комбо → `PCComboData` → (индекс действия) → `PCActionDamageData` → `AttackKey`/`DamageWeight`

Параллельные ветки:
- `PCComboChangeData` — какие индексы комбо заменяются на другие при определённых `KarmaID`, `Master`, `Transcend`;
- `PCComboLevelData` — параметры комбо по уровням;
- `PCActionMonsterLinkData` — события notify и взаимодействия с целью;
- `PCSkillGrowthData` → `StringData_ru.txt` — отображаемые названия и описания;
- `SkillData` / `PCSkillLevelData` → `GameBuffData` — параметры навыков и эффекты, при условии подтверждённого соответствия ID;
- `PCGeneralActionSetData` — условия переходов `CurrentAction` → `NextAction` в общих action set.

## 5. Что ещё нужно, чтобы назвать точные проценты урона

1. Автоматически выгрузить все строки для выбранных героев из `PCComboData`, `PCComboLevelData`, `PCActionDamageData`, `PCActionMonsterLinkData`, `PCComboChangeData`.
2. Проверить уникальность и пересечения ключей. Нельзя соединять по `ComboIndex` без ограничения на актёра/персонажа и контекст.
3. Определить, что означает `AttackWeight` в расчётной системе, и как он соотносится с `DamageWeight`.
4. Проверить пути `DataAssetPath` в `SkillData` и `BluePrint`/`AnimInst` в `PCCharacterData` для логики, которой нет в таблицах.
5. Сверить несколько изолированных ударов в тренировочной зоне при фиксированных характеристиках и без критов. Только после этого строить формулу урона.

## 6. Критерии качества результата

Для каждой восстановленной строки итогового справочника сохранять:
- исходные IDs и названия файлов;
- использованные ключи соединения;
- доказательство типа действия (описание, слот, combo index или action set);
- коэффициент из исходного поля без переименования;
- перевод единиц/коэффициентов только при доказанной формуле;
- confidence: `confirmed`, `probable`, `unresolved`.

Так можно будет обновлять справочник при следующих патчах и понимать, какие значения получены непосредственно из файлов, а какие являются выводом анализа.
