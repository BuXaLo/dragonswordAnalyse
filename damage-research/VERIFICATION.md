## 3. Что подтвердилось

- **Боссы Усмирения.** HP, ATK, DEF, шанс крита, крит. урон, крит. защита: 252 из 252.
- **Статусы** (`MesmerizedData`): ID 1001 / 1002 / 1003 / 1010 / 1009 (6 с, 1 стак), 601 / 501 / 701 / 1004 / 901 (12 с, 3 стака), Холод → Заморозка бафом `9001` на 3-м стаке.
- **DoT.** `ATTACKER#3#0.5#0.75#1`. Для игроков 0.25 / 0.35 / 0.5 (не «ровно в 2 раза»: на 2-м стаке 0.35, а не 0.375). Есть режим с фиксированным уроном 10 / 20 / 30.
- **Крит по уровням.** Вся таблица `BattleAdjustData`, 20 строк.
- **Срезы брони героев:** Кастела, Вероника (11931), Алекс (−10 % … −20 % по уровням), Виола.
- **Множитель крита.** Отношения в замерах совпадают с `1 + CritDMG`.
- **Манекен.** `MonsterUniqueID 900300`, родительский класс `DsMonsterCharacter`; в блюпринте нет зашитых статов. По `MonsterCharacterData`: `StatDefault_ID = 90002` → `StatDefaultData` `Default_Defence = 1000`, `StatTableID = 900300` → `MonsterStatData` (множители статусов, суперармор), `MonsterType = RAID_BOSS`, `SuperArmorStrengthType = VERY_BIG`, `Stat_Type = Fixed`.

## 4. Что уточнил `MonsterStatData.xml`

Подробная таблица — в [DAMAGE_FORMULA.md](DAMAGE_FORMULA.md), раздел 2. Главное:

1. **Множители по статусам лежат в `MonsterStatData`** и читаются как прибавка (у балансных тестовых монстров они равны 0). По умолчанию (1917 из 2052 строк): контроль +100 %, стихии +50 %, срез брони −30 %. Манекен-огр на значениях по умолчанию. Исследование получило свои ×2.0 и ×1.5 именно отсюда.
2. **У боссов значения другие.** Усмирение: контроль +150 % (сложности 1–4), +300 % (5), +200 % (6); Удержание +100 %; стихии +75 %. Рейды Гаурона и Урсулы: контроль +200 %, Удержание +100 %, стихии +75 %. Универсальные ×2.0 и ×1.5 для боссов неверны.
3. **Заморозка** (`FREEZE`) не имеет ни множителя, ни среза брони в `MonsterStatData`. Для контроля срез брони не предусмотрен вовсе.
4. **`AddPer: 2.0` в манекене** относится к набору стихийных статусов при контроле, а не к урону.
5. **Пробитие суперброни.** В `MonsterStatData` для него множителя урона нет; поля `Break*MesAdd_Per` усиливают набор контроля (+100 % у боссов Усмирения). Множитель «1.2–1.5» подтвердить нечем.

### 4.1 «Реакции стихий»

Универсальных реакций «Огонь по Яду +50 %», «Шок по Воде +100 %» в таблицах нет. Эти значения лежат в `GameBuffData` как баффы отдельных монстров (`ATTACKED_MES_ADD_PER`) и усиливают набор шкалы статуса, а не урон (жуки-шлемоносцы: баффы 1194, 1200, 1201, 1202; Энт «мокрый»: 1164). Подробно — в [DAMAGE_FORMULA.md](DAMAGE_FORMULA.md), раздел 4.

## 5. Таблица боссов

Таблица собрана в [BOSSES_EXTENDED.csv](BOSSES_EXTENDED.csv): **36 оригинальных строк перенесены без изменений** (проверено сравнением), справа добавлены данные `MonsterStatData` и 18 строк рейдов. Оригинальный CSV в репозитории я не менял.

**Рейды.** Огр-мясник (рейд Гаурона), Гаурон (человеческая и драконья формы), Урсула (человеческая форма, драконья форма, драконья форма 2). Для каждой формы по три сложности, подписанные «Обычная / Сложная / Очень сложная» по пометкам в таблице данных. Названия «Огр-мясник» и «Огр (манекен)» взяты из клиентской локализации; названия форм — мой перевод. Соответствие между `StatDefaultData` и `MonsterStatData` для всех 54 строк проверено по `MonsterCharacterData` (`StatDefault_ID` и `StatTableID`), в том числе «драконья форма 2» Урсулы = запись «вершина». У всех этих боссов `Stat_Type = Fixed`; колонки типа монстра, суперармора и `MultiplayAdjust_ID` в CSV взяты оттуда. Рейд Казака в `StatDefaultData` строк не имеет.

## 6. Формула урона

Развёрнуто в [DAMAGE_FORMULA.md](DAMAGE_FORMULA.md). Кратко:

- Крит точный (1.8928 в трёх новых замерах Астрии).
- Броня: структура верна. Защита манекена = 1000 подтверждена таблицами и совпала со значением, выведенным из замеров Астрии по рейдовому огру (1000.00). При ней `K = 1200` несовместим с замерами (минимальная броня `A = 0.5455` против наблюдаемых 0.5279 и 0.5928); подбор по четырём старым замерам даёт `K ≈ 1000` при двух разных значениях игнорирования, замеры Астрии дают `K = 1000.0`. Значения 1200 (и защита, и K) из исследования замерами не подтверждаются.
- Круглое `K` получается только при структуре исследования: бонусы игнорирования складываются (13.79 + 20), пробитие вычитается после игнорирования.

## 8. Мелочи

- **`DsHF_IgnoreDamage.json`** описан как «неуязвимость». Все шесть команд игнорируют только обработку HP и навыков; суперармор, статусы и эффекты попадания остаются включёнными.
- **`DsReaction_PCMonster.json`:** `RisingRate = 0.5`, `MinRisingSpeed = 600` подтверждены; «длительность лежания» — интерпретация.
- **Вероника, маунт.** Исследование: «−5 % и −15 % тяжёлая атака» (из текста локализации). В таблице оба эффекта дают −5 % по защите (`11902`, `11903`), а `11903` ещё и −20 % атаки; −15 % в таблице нет ([разбор Вероники](../Veronica/VERONICA_SKILLS.md)).
- **Таблица `EStatType`.** ID 1, 2, 3, 7, 8, 9 (ATK, DEF, HP и их проценты) совпадают с порядком `StatListData.xml`; остальные (5 и 6 как шанс и урон крита, 11 и 12 как их проценты) расходятся: в списке это скорость атаки и движения. Использовать как справочник нельзя.
- **`OffenceCategoryData.xml`** хранит `PropBreakRate` по типам атаки (`BLUNT 1.3`, `BLAST 1.5`, `BOSS_UNIQUE_ATTACK 100`); судя по названию, это разрушение объектов, а не суперброни.

## 10. Рекомендуемые правки в самом исследовании

1. Генеральная формула: «контроль ×2.0, стихии ×1.5» оговорить как значения обычных монстров; для боссов взять таблицу из [DAMAGE_FORMULA.md](DAMAGE_FORMULA.md).
2. Реакции стихий: заменить универсальные множители на описание баффов отдельных монстров (набор статусов).
3. Заморозку убрать из строк с ×2.0 и −30 % брони.
4. Пробитие: убрать «1.2–1.5» или найти источник.
5. Колонки слабостей и сопротивлений боссов: сверить с порогами `MesResist` (раздел 5).
6. Веса ударов: убрать «0.075, 0.234» и «Ария = 1.0» либо добавить данные.
7. Тики по игрокам: «ровно в 2 раза» заменить на 0.25 / 0.35 / 0.5.
8. Таблицу `EStatType` пометить как непроверенную.
9. Таблицу героев дополнить T1 / T3 / T6 и пометками «Скоро в обновлении».
10. Константу `K = 1200` заменить на `K = 1000`, защиту манекена-огра на 1000 (подтверждена `MonsterCharacterData` 900300 → `StatDefaultData` 90002); колонку «Поглощение броней» пересчитать по `DEF/(DEF+1000)`.
